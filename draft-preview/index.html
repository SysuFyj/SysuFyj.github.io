LLM 注意力机制及优化：从单 token 解码到稀疏与线性注意力

2026-09-23 21:00:00

本文是根据手写笔记整理的第一版草稿。主线、术语顺序和重点遵照原笔记；涉及 QSA、CSA、HCA 的部分，笔记中的缩写尚不能与某一篇公开论文一一对应，文中会明确标注工作性解释，待后续核对。

一、注意力机制的梳理

1. 从文字到 Q、K、V

LLM 接收的不是“字”本身，而是一串 token。输入文本首先经过 tokenizer，被切分成 token，再通过 embedding 查表得到向量。设一段输入包含 TT 个 token，每个 token 的隐藏维度为 DD，那么输入可以写成矩阵

X∈ℝT×D. X \in \mathbb{R}^{T \times D}.

在一个注意力层中，输入隐藏状态分别经过三个线性变换：

Q=XWQ,K=XWK,V=XWV. Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V.

这里不妨把三个向量理解成三个不同的问题：

  • Q（Query）：当前 token 想从上下文中寻找什么；
  • K（Key）：每个历史 token 可以被什么样的查询匹配；
  • V（Value）：匹配成功后，真正要取回的内容。

因此，QQ 和 KK 负责“匹配”，VV 负责“提供信息”。对第 tt 个 token 而言，它会用自己的查询向量 qtq_t 与当前可见的 key 做点积，得到一组分数：

st,i=qtki⊤dk. s_{t,i}=\frac{q_t k_i^\top}{\sqrt{d_k}}.

除以 dk\sqrt{d_k} 是为了控制点积的数值范围，避免 softmax 输入过大而造成梯度不稳定。随后对分数做 softmax，得到注意力权重

αt,i=softmax⁡(st,i), \alpha_{t,i}=\operatorname{softmax}(s_{t,i}),

再对 value 加权求和：

ot=∑i≤tαt,ivi. o_t=\sum_{i\le t}\alpha_{t,i}v_i.

这个 oto_t 是当前层的注意力输出，它仍然是一个向量，并不是下一个 token。经过输出投影、残差连接、前馈网络和后续 Transformer 层之后，最终隐藏状态才会送入 LM Head，得到词表上的 logits，再经过 softmax 得到下一个 token 的概率分布。

容易混淆的三个对象：注意力分数是 qtki⊤q_tk_i^\top，注意力权重是 softmax 后的 αt,i\alpha_{t,i}，注意力输出是加权后的 oto_t。真正的“新 token”由最后的语言模型头生成。

2. Prefill 和 Decode：一个 token 怎样被生成

推理可以分成两个阶段：Prefill 和 Decode。

2.1 Prefill：先处理已有上下文

用户一次输入一段上下文 x1,…,xnx_1,\ldots,x_n 时，模型会在因果 mask 下并行计算这 nn 个位置。第 tt 个位置只能看到 x1,…,xtx_1,\ldots,x_t，不能看到未来 token。这个阶段的主要工作有两件：

  1. 计算上下文各位置的隐藏状态和注意力输出；
  2. 把每一层已经得到的 K1,…,KnK_1,\ldots,K_n 和 V1,…,VnV_1,\ldots,V_n 保存下来，形成 KV cache。

Prefill 的计算量通常随上下文长度增长得很快，但它可以利用矩阵乘法并行处理多个 token。

2.2 Decode：每轮只生成一个新 token

Prefill 得到最后一个位置的输出后，LM Head 产生第一个待生成 token。之后进入自回归 Decode：

  1. 把上一轮生成的 token 输入下一轮；
  2. 当前隐藏状态 hth_t 只生成新的 qt,kt,vtq_t,k_t,v_t；
  3. qtq_t 与 KV cache 中的 K1:tK_{1:t} 做匹配；
  4. 用权重读取 V1:tV_{1:t}，得到当前层输出 oto_t；
  5. 经过所有层和 LM Head，得到 xt+1x_{t+1}；
  6. 把新产生的 kt,vtk_t,v_t 追加到 cache，进入下一轮。

Decode 时不需要重新计算旧 token 的 K,VK,V，这就是 KV cache 的意义。但它也带来新的瓶颈：序列越长，缓存越大；每生成一个 token，都要从显存读取越来越长的 K,VK,V。因此，注意力优化通常围绕两个问题展开：能否少存一些状态，能否少读或少算一些 token。

3. MHA、GQA 和 MQA

设模型有 HH 个 query head。

机制 Q head K/V 的组织 KV cache 特点
MHA HH 个 每个 query head 都有自己的 K/V 表达能力强，缓存最大
GQA HH 个 若干 query head 共享一组 K/V 在质量和缓存之间折中
MQA HH 个 所有 query head 共享一组 K/V 缓存和带宽开销最小，但可能损失表达能力

GQA 和 MQA 的共同思路是：保留多个不同的查询视角，但减少 key/value 的副本。它们主要降低的是 head 维度上的缓存数量，并没有改变“每个新 query 仍然要面对历史 token”这一事实。MLA、线性注意力和稀疏注意力，则从缓存表示或 token 数量上继续优化。

二、注意力机制的几条优化路线

1. Qwen：Gated Attention 与 Gated DeltaNet

1.1 Gated Attention：给注意力输出加一个可学习的门

标准 scaled dot-product attention 得到 oto_t 后，可以再计算一个门控向量 gtg_t，用 sigmoid 把它限制在 00 到 11 附近：

õt=σ(gt)⊙ot. \tilde{o}_t=\sigma(g_t)\odot o_t.

门控可以是 head-specific 的，也可以依赖当前 query。它并没有改变 Q、K 的匹配过程，而是让模型在得到注意力结果后，决定哪些通道或哪些头的结果应该被保留、抑制或缩小。Qwen 团队的实验把这种简单的 output gating 与三点联系起来：

  • 在 softmax attention 的低秩映射之后增加非线性；
  • 用 query-dependent 的门控分数产生稀疏的输出调制；
  • 缓解 massive activation、attention sink，并改善长上下文外推。

所以，Gated Attention 的关键是“注意力算完之后再控制信息流”。它和 GDN 不是同一个东西：前者仍然是 softmax attention 的输出门，后者是线性注意力/递归状态更新机制。Qwen 的混合架构可以把两者放在不同层中协同使用。Qwen 论文明确报告，效果最好的 SDPA output gating 被用于 Qwen3-Next；Qwen3.5 的公开介绍则把 Gated DeltaNet 作为混合架构中的线性注意力组件。

1.2 GDN：把长序列 KV 变成门控的有限状态

Gated DeltaNet 可以从“不断更新一块记忆矩阵”的角度理解。与每个历史 token 都保存一份 K,VK,V 不同，它维护一个随时间更新的状态 StS_t。一个简化的概念式是：

St≈λt⊙St−1+delta-update(kt,vt),ot=Stqt. S_t\approx \lambda_t\odot S_{t-1}+\text{delta-update}(k_t,v_t), \qquad o_t=S_tq_t.

其中 λt\lambda_t 是遗忘或保留门，delta update 则根据当前的 kt,vtk_t,v_t 修正已有记忆。它的直觉是：

  • 新 token 不是简单地追加到无限长的列表里，而是更新有限状态；
  • 门控决定旧记忆保留多少，新信息写入多少；
  • 查询读取的是状态 StS_t，而不是逐一读取所有历史 token。

因此，GDN 的状态更新更接近线性复杂度的递归记忆，适合与少数保留完整检索能力的 attention 层交替组成混合架构。代价是：有限状态必须学会压缩历史信息，某些需要精确回看远处原文的任务仍然更依赖 full attention 或稀疏检索层。

2. MLA 与 KDA：压缩缓存，或把缓存变成状态

2.1 MLA：先压缩，再在需要时恢复

DeepSeek-V2 提出的 Multi-head Latent Attention（MLA）不是简单地把每个 head 的 K/V 复制减少，而是把 key 和 value 联合压缩到一个共享的低秩 latent 向量：

ctKV=WDKVht. c_t^{KV}=W_{DKV}h_t.

推理时主要缓存 ctKVc_t^{KV}，而不是完整的 kt,vtk_t,v_t。概念上，需要注意力计算时，再通过上投影恢复内容相关的 key/value：

ktC=WUKctKV,vt=WUVctKV. k_t^C=W_{UK}c_t^{KV},\qquad v_t=W_{UV}c_t^{KV}.

位置编码是 MLA 中容易混淆的部分。若把 RoPE 直接施加到低秩 latent 上，位置旋转会和内容压缩耦合。MLA 因此把内容分支和位置分支拆开：内容信息保存在 ctKVc_t^{KV}，位置相关的 key/query 分量单独处理。这样既保留位置信息，又可以在缓存中主要保存低维 latent。

从工程上看，MLA 的收益在于：缓存条目仍然对应历史 token，但每个条目的维度大幅缩小；某些上投影还可以吸收到 query 或输出投影中，使推理时不必显式恢复完整 K/V。DeepSeek-V2 的原论文把这一点概括为 low-rank key-value joint compression。

2.2 KDA：把 Gated DeltaNet 做得更细

Kimi Linear 中的 Kimi Delta Attention（KDA）可以看作 Gated DeltaNet 的更细粒度版本。它保留 delta rule 的“更新有限状态”思路，同时使用更细的门控去控制不同维度、不同状态分量的写入和遗忘：

St=forgett(St−1)+deltat(kt,vt),ot=Stqt. S_t=\text{forget}_t(S_{t-1})+\text{delta}_t(k_t,v_t), \qquad o_t=S_tq_t.

这里的重点不是某一个固定公式，而是门控粒度：如果只有一个粗粒度门，模型只能整体保留或整体遗忘；更细粒度的门允许它在状态中保留不同类型的信息。Kimi Linear 的整体结构是 KDA 与 MLA 的层间混合：一部分层用线性注意力状态处理长序列，一部分层用 MLA 保留更强的内容检索能力。这样形成了一个折中：

  • KDA 负责低缓存、线性读取和持续更新；
  • MLA 负责压缩后的全局检索；
  • 两者共同避免所有层都承担完整 KV cache 的成本。

这里也要区分两个方向：MLA 是“把每个 token 的缓存压小”，KDA 是“让历史 token 进入有限状态”。前者仍保留 token 对应的 latent，后者更像一个递归记忆系统。

3. DeepSeek DSA：先索引，再只对少量 token 做注意力

手写笔记中在这里同时出现了 “QSA” 和 “DSA”。公开的 DeepSeek-V3.2 技术报告正式使用的名称是 DeepSeek Sparse Attention（DSA）；下文把笔记里的 QSA 理解为“由 query 驱动的候选 token 索引/选择阶段”，不把它当作另一个已经确认的官方模块。

DSA 的核心是两阶段：

  1. Lightning indexer：用一个更小、更便宜的索引器，为当前 query 与历史 token 计算相关性分数；
  2. Fine-grained token selection：只取 index score 最高的 top-kk 个 token 的 KV，交给真正的 attention。

可以把它写成：

It,s=Indexer(ht,hs),𝒮t=TopK⁡s(It,s), I_{t,s}=\text{Indexer}(h_t,h_s), \qquad \mathcal{S}_t=\operatorname{TopK}_s(I_{t,s}),

ot=Attn⁡(qt,{ks,vs}s∈𝒮t). o_t=\operatorname{Attn}\bigl(q_t,\{k_s,v_s\}_{s\in\mathcal{S}_t}\bigr).

关键点是：索引器不必和完整 attention 一样昂贵，它只负责回答“哪些 token 值得被真正读取”。主 attention 的 token 数从 LL 缩小到 kk，因此核心注意力部分由 O(L2)O(L^2) 变成近似 O(Lk)O(Lk)。索引过程本身也要付出成本，所以 DSA 的工程价值取决于索引器是否足够轻、top-k 选择是否足够稳定，以及硬件是否能高效读取不连续的 KV 条目。

4. CSA、HCA 与 SWA：从笔记抽象出的组合策略

这一组缩写在手写笔记中更像是对稀疏注意力设计空间的归纳，而不是一组已经确认的 DeepSeek 官方组件。按照笔记中的“先压缩、再筛选、再局部计算”的逻辑，可以整理成下面的工作性解释。

4.1 CSA：先把 KV 做粗粒度压缩

CSA 可以理解为先把历史 token 按连续块或语义区域组织起来，为每个块建立一个压缩表示。当前 query 先与块表示匹配，再决定哪些块值得展开。这样做的好处是先减少候选数量，坏处是块内的细节可能被平均掉；如果重要 token 与不重要 token 混在同一块里，粗粒度压缩会损失检索精度。

4.2 HCA：保留高价值 token，再处理剩余区域

HCA 可以理解为 heavy-hitter 或 high-coverage 的保留策略：某些 token 在较长时间内经常被访问，或者对全局语义十分重要，就把它们作为长期保留项；其余 token 再通过窗口、块压缩或 query 选择处理。它解决的是“不能只看最近 token”的问题：系统需要给少数全局锚点留下长期通道。

4.3 SWA：滑动窗口保留局部连续性

Sliding Window Attention（SWA）只让 query 关注最近的 WW 个 token：

𝒮t={t−W+1,…,t}. \mathcal{S}_t=\{t-W+1,\ldots,t\}.

它对局部语言建模很有效，缓存和计算都容易控制，但会丢掉窗口之外的远程信息。因此实际系统常把 SWA 与全局 token、压缩摘要或少量检索头结合：窗口负责“最近发生了什么”，全局保留项负责“整段上下文中哪些内容不能忘”。

把这几种思路放在一起，可以得到一条清晰的组合路线：SWA 提供稳定的局部窗口，HCA 保留少量全局重要 token，CSA 对大范围历史做块级压缩，QSA/DSA 用 query 做最后的细粒度选择。 这比单独使用某一种策略更灵活，但也增加了索引、内存布局和训练稳定性的复杂度。

三、把这些方法放回同一个问题

从单 token Decode 的公式看，注意力的成本主要来自三处：

  1. 存储：历史 token 的 K/V 越多，KV cache 越大；
  2. 读取：每次新 query 都要读取一段历史 K/V；
  3. 计算：query 与候选 key 的匹配及 value 聚合会随候选数量增加。

不同方法的目标并不完全一样：

  • Gated Attention 主要控制输出的信息流；
  • GDN/KDA 把历史 token 变成门控的有限状态；
  • GQA/MQA 减少 K/V head 的副本；
  • MLA 把每个 token 的 K/V 压成低秩 latent；
  • DSA/QSA 先索引再选择少量 token；
  • CSA/HCA/SWA 分别从块压缩、全局重要 token 和局部窗口控制读取范围。

因此，“优化注意力”不是简单地让某一个公式更快，而是在三个层面做取舍：保留什么信息、把信息存在哪里、当前 query 读取哪些信息。理想的架构往往是混合的：局部窗口保证稳定的短程建模，稀疏检索负责远程查找，低秩或递归状态负责压缩缓存，门控则控制各个分支最终写回多少信息。

术语与待核对项

  1. 手写页中的 “QSA” 与 DeepSeek-V3.2 技术报告中的 DSA 可能指同一条“query/index/top-k”思路，也可能是你想区分的两个方案；本文暂按“QSA 是选择阶段，DSA 是完整机制”处理。
  2. CSA、HCA 在笔记中没有展开全称；本文使用的是便于理解的工作性解释，不把它们写成已确认的官方模块。
  3. Gated Attention 与 GDN 是两个不同层次的概念：前者是 softmax attention 输出门，后者是带门控的线性/递归注意力。Qwen 的混合架构可能同时包含两者，但不能把二者等同。
  4. MLA 的位置分支、KDA 的门控形式和不同实现的融合层数需要根据具体模型配置继续补充。本文先解释思路，不记录未经核对的维度和层数。
