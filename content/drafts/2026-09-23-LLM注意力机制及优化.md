## 一、注意力机制的梳理

### 1. 从文字到 Q、K、V

LLM 接收的不是“字”本身，而是一串 token。输入文本首先经过 tokenizer，被切分成 token，再通过 embedding 查表得到向量。设一段输入包含 $T$ 个 token，每个 token 的隐藏维度为 $D$，那么输入可以写成矩阵

\[
X \in \mathbb{R}^{T \times D}.
\]

在一个注意力层中，输入隐藏状态分别经过三个线性变换：

\[
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V.
\]

这里不妨把三个向量理解成三个不同的问题：

- **Q（Query）**：当前 token 想从上下文中寻找什么；
- **K（Key）**：每个历史 token 可以被什么样的查询匹配；
- **V（Value）**：匹配成功后，真正要取回的内容。

因此，$Q$ 和 $K$ 负责“匹配”，$V$ 负责“提供信息”。对第 $t$ 个 token 而言，它会用自己的查询向量 $q_t$ 与当前可见的 key 做点积，得到一组分数：

\[
s_{t,i}=\frac{q_t k_i^\top}{\sqrt{d_k}}.
\]

除以 $\sqrt{d_k}$ 是为了控制点积的数值范围，避免 softmax 输入过大而造成梯度不稳定。随后对分数做 softmax，得到注意力权重

\[
\alpha_{t,i}=\operatorname{softmax}(s_{t,i}),
\]

再对 value 加权求和：

\[
o_t=\sum_{i\le t}\alpha_{t,i}v_i.
\]

这个 $o_t$ 是当前层的注意力输出，它仍然是一个向量，并不是下一个 token。经过输出投影、残差连接、前馈网络和后续 Transformer 层之后，最终隐藏状态才会送入 LM Head，得到词表上的 logits，再经过 softmax 得到下一个 token 的概率分布。

> **容易混淆的三个对象**：注意力分数是 $q_tk_i^\top$，注意力权重是 softmax 后的 $\alpha_{t,i}$，注意力输出是加权后的 $o_t$。真正的“新 token”由最后的语言模型头生成。

### 2. Prefill 和 Decode：一个 token 怎样被生成

推理可以分成 **Prefill** 和 **Decode** 两个阶段。理解这两个阶段时，最容易漏掉的一点是：**每一层 Transformer 都有自己独立的 KV cache**。层与层之间传递的是当前 token 的 hidden state，而不是把某一层的 K/V 直接交给下一层。

设模型共有 $L$ 层，输入 hidden state 为 $H^{(0)}=X$。第 $l$ 层接收上一层的 $H^{(l-1)}$，用自己的投影矩阵产生 $Q^{(l)},K^{(l)},V^{(l)}$，并维护本层的缓存：

\[
C^{(l)}=\{(K_i^{(l)},V_i^{(l)})\}_{i=1}^{t}.
\]

因此，第 $l$ 层的 cache 只服务于第 $l$ 层；不同层不会共享同一份 K/V。

#### 2.1 Prefill：先把已有上下文写入每一层的 cache

用户一次输入 $x_1,\ldots,x_n$ 时，模型在因果 mask 下并行处理这 $n$ 个位置。第 $t$ 个位置只能看到 $x_1,\ldots,x_t$。对每一层来说，Prefill 会完成两件事：

1. 用本层的参数计算每个位置的 query、key、value 以及注意力输出；
2. 把本层所有位置的 $K_1^{(l)},\ldots,K_n^{(l)}$ 和 $V_1^{(l)},\ldots,V_n^{(l)}$ 写入本层的 $C^{(l)}$。

Prefill 可以用矩阵乘法并行处理多个 token，但它要在所有层都建立一份与上下文长度对应的 cache。

#### 2.2 Decode：从第一层开始，逐层传递 hidden state

Prefill 得到最后一个位置的输出后，LM Head 产生第一个待生成 token。生成下一个 token 时，流程可以写成：

1. 新 token $x_t$ 先进入 embedding，得到第 $0$ 层输入 $h_t^{(0)}$；
2. 在第 $1$ 层，$h_t^{(0)}$ 经过本层投影得到 $q_t^{(1)},k_t^{(1)},v_t^{(1)}$。$q_t^{(1)}$ 访问第 $1$ 层从第一个 token 到当前位置的 $C^{(1)}$，得到 $h_t^{(1)}$，并把新的 $k_t^{(1)},v_t^{(1)}$ 追加进去；
3. $h_t^{(1)}$ 作为第 $2$ 层输入，重复同样的过程，直到第 $L$ 层得到 $h_t^{(L)}$；
4. 最终的 $h_t^{(L)}$ 送入 LM Head，得到下一个 token 的概率分布。

对第 $l$ 层，可以把这一步简写成：

\[
h_t^{(l-1)}\ \longrightarrow\ q_t^{(l)},k_t^{(l)},v_t^{(l)}
\ \longrightarrow\ h_t^{(l)}=\operatorname{Block}_l\bigl(h_t^{(l-1)},C_{1:t}^{(l)}\bigr).
\]

所以“从第一个 token 开始算”准确地说，是**每一层的新 query 都可以读取从 token 1 到当前位置的本层 cache**；并不是每生成一个 token，就把历史 token 从第一层到最后一层重新计算一遍。旧 token 的 K/V 已经保存在各层自己的 cache 中，Decode 只需计算当前 token 在每一层的新投影并追加新条目。

Decode 的瓶颈也因此分成三部分：历史 K/V 越多，**存储**越大；每一层都要从 cache 中取出可见历史，**读取**越多；query 与这些历史 key 做匹配并聚合 value，**计算**也越多。

### 3. MHA、GQA 和 MQA

![MHA、GQA 与 MQA 的 K/V 共享方式](/images/llm-attention/attention-variants.svg)

设模型有 $H$ 个 query head。

| 机制 | Q head | K/V 的组织 | KV cache 特点 |
| --- | --- | --- | --- |
| **MHA** | $H$ 个 | 每个 query head 都有自己的 K/V | 表达能力强，缓存最大 |
| **GQA** | $H$ 个 | 若干 query head 共享一组 K/V | 在质量和缓存之间折中 |
| **MQA** | $H$ 个 | 所有 query head 共享一组 K/V | 缓存和带宽开销最小，但可能损失表达能力 |

GQA 和 MQA 的共同思路是：保留多个不同的查询视角，但减少 key/value 的副本。它们主要降低的是 **head 维度上的缓存数量**，并没有改变“每个新 query 仍然要面对历史 token”这一事实。MLA、线性注意力和稀疏注意力，则从缓存表示或 token 数量上继续优化。

同一层里的不同 head 也不是重复计算：它们各自有不同的 $W_Q,W_K,W_V$，会在训练中形成不同的关注视角。有的 head 更偏向局部语法和邻近 token，有的擅长长距离指代或实体检索，有的对位置边界、分隔符或结构模式更敏感。模型并不会手工规定“第几个 head 必须负责什么”，这些分工是训练后涌现出来的。各 head 得到的输出会拼接起来，再经过输出投影写回这一层的 hidden state。GQA 和 MQA 保留了多个 query head 的视角，只是让若干 query head 共享 K/V。

## 二、注意力机制的几条优化路线

![注意力优化路线图](/images/llm-attention/optimization-map.svg)

### Qwen：Gated Attention 与 Gated DeltaNet

#### Gated Attention：给注意力输出加一个可学习的门

标准 scaled dot-product attention 得到 $o_t$ 后，可以再计算一个门控向量 $g_t$，用 sigmoid 把它限制在 $0$ 到 $1$ 附近：

\[
\tilde{o}_t=\sigma(g_t)\odot o_t.
\]

门控可以是 head-specific 的，也可以依赖当前 query。它并没有改变 Q、K 的匹配过程，而是让模型在得到注意力结果后，决定哪些通道或哪些头的结果应该被保留、抑制或缩小。Qwen 团队的实验把这种简单的 output gating 与三点联系起来：

- 在 softmax attention 的低秩映射之后增加非线性；
- 用 query-dependent 的门控分数产生稀疏的输出调制；
- 缓解 massive activation、attention sink，并改善长上下文外推。

所以，Gated Attention 的关键是“**注意力算完之后再控制信息流**”。它和 GDN 不是同一个东西：前者仍然是 softmax attention 的输出门，后者是线性注意力/递归状态更新机制。Qwen 的混合架构可以把两者放在不同层中协同使用。Qwen 论文明确报告，效果最好的 SDPA output gating 被用于 Qwen3-Next；Qwen3.5 的公开介绍则把 Gated DeltaNet 作为混合架构中的线性注意力组件。

#### GDN：把长序列 KV 变成门控的有限状态

Gated DeltaNet 可以从“不断更新一块记忆矩阵”的角度理解。与每个历史 token 都保存一份 $K,V$ 不同，它维护一个随时间更新的状态 $S_t$。一个简化的概念式是：

\[
S_t\approx \lambda_t\odot S_{t-1}+\text{delta-update}(k_t,v_t),
\qquad o_t=S_tq_t.
\]

其中 $\lambda_t$ 是遗忘或保留门，delta update 则根据当前的 $k_t,v_t$ 修正已有记忆。它的直觉是：

- 新 token 不是简单地追加到无限长的列表里，而是更新有限状态；
- 门控决定旧记忆保留多少，新信息写入多少；
- 查询读取的是状态 $S_t$，而不是逐一读取所有历史 token。

因此，GDN 的状态更新更接近线性复杂度的递归记忆，适合与少数保留完整检索能力的 attention 层交替组成混合架构。代价是：有限状态必须学会压缩历史信息，某些需要精确回看远处原文的任务仍然更依赖 full attention 或稀疏检索层。

### MLA 与 KDA：压缩缓存，或把缓存变成状态

#### MLA：在每个 token 的存储维度上做压缩

MLA 的核心不是简单减少 K/V head 的数量，而是把**每个历史 token 的缓存条目压到更低的维度**。在第 $l$ 层，先用一个低秩下投影把 hidden state 压成 latent：

\[
c_t^{KV}=W_D^{KV}h_t^{(l)}.
\]

推理时主要存储 $c_t^{KV}$，而不是完整的 $k_t,v_t$。这里的 $W_D^{KV}$ 就是把高维 hidden state 映射到低维存储空间的矩阵，因此 MLA 直接减少的是每个 token 的 cache 维度。

为什么压缩后的 $c_t^{KV}$ 仍然有用？因为模型可以用另外的上投影从这个低秩表示中恢复注意力需要的不同分支：

\[
k_t^C=W_U^Kc_t^{KV},\qquad v_t=W_U^Vc_t^{KV}.
\]

其中 $k_t^C$ 和 $v_t$ 负责内容信息。位置部分不与内容强行揉在一起，而是用独立的低维分支和上投影恢复参与打分所需的 RoPE 分量，例如 $k_t^R=W_U^R c_t^R$，再对它施加 RoPE。也就是说，模型用不同的可学习矩阵分别恢复内容分支和位置分支：低秩 latent 保留内容，独立的 RoPE 分支补上位置信息。这里的“恢复”不是把每个历史 token 的完整 K/V 永久还原，而是只生成注意力计算需要的分量。

推理时还不必把每个历史 token 的完整 K/V 全部还原出来。矩阵乘法满足结合律，例如：

\[
q_t^{\top}(W_U^Kc_s^{KV})
= (W_U^{K\top}q_t)^{\top}c_s^{KV}.
\]

因此，可以先把当前 query 变换到低维空间，再直接与缓存中的 $c_s^{KV}$ 做匹配；value 侧的上投影也可以吸收到后续的输出变换中。这样做的本质是：**不重建完整 KV cache，而是让 query 去读取低维 latent**。训练会学习一个足以保留有效内容的瓶颈，RoPE 分支则保留位置辨识能力。

所以，MLA 的收益可以用一句话概括：**每个 token 仍有自己的缓存表示，但这个表示的存储维度被压小了**。它和 GQA/MQA 的区别在于，GQA/MQA 主要减少 head 维度上的 K/V 副本，MLA 则进一步压缩每个 token 的存储条目。

#### KDA：把 Gated DeltaNet 做得更细

Kimi Linear 中的 Kimi Delta Attention（KDA）可以看作 Gated DeltaNet 的更细粒度版本。它保留 delta rule 的“更新有限状态”思路，同时使用更细的门控去控制不同维度、不同状态分量的写入和遗忘：

\[
S_t=\text{forget}_t(S_{t-1})+\text{delta}_t(k_t,v_t),
\qquad o_t=S_tq_t.
\]

这里的重点不是某一个固定公式，而是门控粒度：如果只有一个粗粒度门，模型只能整体保留或整体遗忘；更细粒度的门允许它在状态中保留不同类型的信息。Kimi Linear 的整体结构是 KDA 与 MLA 的层间混合：一部分层用线性注意力状态处理长序列，一部分层用 MLA 保留更强的内容检索能力。这样形成了一个折中：

- KDA 负责低缓存、线性读取和持续更新；
- MLA 负责压缩后的全局检索；
- 两者共同避免所有层都承担完整 KV cache 的成本。

这里也要区分两个方向：MLA 是“**把每个 token 的缓存压小**”，KDA 是“**让历史 token 进入有限状态**”。前者仍保留 token 对应的 latent，后者更像一个递归记忆系统。

### DeepSeek DSA：先索引，再只对少量 token 做注意力

公开的 DeepSeek-V3.2 技术报告把这条路线正式称为 **DeepSeek Sparse Attention（DSA）**。它先用便宜的索引器估计当前 query 与历史 token 的相关性，再只对排名靠前的 token 做完整 attention：

1. **Lightning indexer**：用更小、更便宜的索引器，为当前 query 与历史 token 计算相关性分数；
2. **Fine-grained token selection**：取 index score 最高的 top-$k$ 个 token 的 KV，交给真正的 attention。

可以写成：

\[
I_{t,s}=\operatorname{Indexer}(h_t,h_s),
\qquad \mathcal{S}_t=\operatorname{TopK}_s(I_{t,s}),
\]

\[
o_t=\operatorname{Attn}\bigl(q_t,\{k_s,v_s\}_{s\in\mathcal{S}_t}\bigr).
\]

DSA 的主要收益来自**少读、少算**：主 attention 面对的 token 数从 $L$ 缩小到 $k$，核心部分由 $O(L^2)$ 变成近似 $O(Lk)$。它本身通常不等于把历史 KV 存储压缩掉；如果底层仍保留完整 KV cache，存储量并不会因为 top-$k$ 选择自动消失。DSA 可以和 MLA 组合，此时 MLA 负责压缩每个 token 的存储维度，DSA 负责从这些缓存条目中选择当前要读取的部分。

笔记中的 QSA 可以放在同一类“query/key 驱动选择”的位置理解：它描述的是用轻量索引或 query 相关性找候选 token 的思路；DSA 则是把索引、top-k 选择和主 attention 组合起来的完整机制。

### CSA、HCA 与 SWA：压缩、全局保留和局部窗口

CSA、HCA、SWA 与 DSA/QSA 都可以用于稀疏化注意力，但它们关注的瓶颈不同。**CSA 和 HCA 先改变历史的存储表示，DSA/QSA 主要决定当前读取哪些条目，SWA 则用固定窗口限制可见范围。**这些方法可以并列组合，不必理解成一条固定的先后流水线。

#### CSA：压缩稀疏注意力

**CSA（Compressed Sparse Attention）**先把历史压缩成更少的 KV 条目，例如按连续块、语义区域或摘要单元形成压缩表示；然后当前 query 先在这些压缩条目中筛选，再只对选中的条目计算 attention。由于历史在写入或维护时已经被压成更少的条目，CSA 同时减少：

- **存储**：cache 中保存的 KV 条目更少；
- **读取**：query 不必扫描全部原始 token；
- **计算**：主 attention 只处理筛选后的压缩条目。

它的代价是压缩会损失细节，尤其当同一个块里混有重要和不重要 token 时，摘要可能无法精确恢复原文。

#### HCA：重度压缩注意力

**HCA（Heavy/Highly Compressed Attention）**比 CSA 采用更强的历史压缩，把更长的片段聚合成更少的条目，再对这些压缩后的条目做全局 attention。它强调“压得更狠、仍保持全局可见”：存储量和读取量都能进一步下降，但信息损失和训练难度也更高。

CSA 与 HCA 的差别可以这样记：CSA 是较温和的压缩后稀疏选择，仍会从部分压缩条目中读取；HCA 是更重的压缩，直接在压缩后的全局条目上做注意力。二者都在**存储和计算**上动手，而不只是读取阶段的 top-k。

#### SWA：滑动窗口保留局部连续性

**SWA（Sliding Window Attention）**只让 query 关注最近的 $W$ 个 token：

\[
\mathcal{S}_t=\{t-W+1,\ldots,t\}.
\]

它的 cache、读取和计算都容易控制，但窗口之外的远程信息会被截断。因此实际系统常把 SWA 与少量全局 token、压缩摘要或 DSA 检索结合：窗口负责最近上下文，全局通道负责远处的重要信息。

#### 与 DSA/QSA 的区别

DSA/QSA 的核心是**选择**：历史通常仍按原有形式存储，轻量索引器只决定当前 query 要读哪些 token，所以主要节省读取带宽和主 attention 的计算。CSA/HCA 的核心是**存储表示本身已经被压缩**，因此在读取和计算之外，还直接减少 KV cache 的容量。SWA 则不依赖内容相关性，按照固定位置窗口选择，稳定但可能漏掉远程关键 token。

## 三、把这些方法放回同一个问题

从单 token Decode 的公式看，注意力的成本主要来自三处：

1. **存储**：历史 token 的 K/V 越多，KV cache 越大；
2. **读取**：每次新 query 都要读取一段历史 K/V；
3. **计算**：query 与候选 key 的匹配及 value 聚合会随候选数量增加。

不同方法的目标并不完全一样：

- Gated Attention 主要控制输出的信息流；
- GDN/KDA 把历史 token 变成门控的有限状态；
- GQA/MQA 减少 K/V head 的副本；
- MLA 把每个 token 的 K/V 压成低秩 latent；
- DSA/QSA 先索引再选择少量 token；
- CSA/HCA/SWA 分别从块压缩、全局重要 token 和局部窗口控制读取范围。

因此，“优化注意力”不是简单地让某一个公式更快，而是在三个层面做取舍：**保留什么信息、把信息存在哪里、当前 query 读取哪些信息**。理想的架构往往是混合的：局部窗口保证稳定的短程建模，稀疏检索负责远程查找，低秩或递归状态负责压缩缓存，门控则控制各个分支最终写回多少信息。
